🚀 Câu hỏi 1 — Latency là bao nhiêu?

Tổng thời gian trả lời 1 câu hỏi (đo bằng time.perf_counter() quanh lúc gửi → nhận response, model gemini-2.5-flash-lite):

  • Stage 5 (phân tán): 23.59 giây — request đi qua test_client → Customer(10100) → Law(10101) → Tax(10102) ‖ Compliance(10103) → aggregate, mỗi hop là 1 lời gọi HTTP + serialize + 1 vòng Gemini.
  • Stage 4 (in-process): 8.09 giây — cùng logic nhưng gọi hàm trực tiếp trong 1 process. Chênh ~15.5s chính là chi phí của kiến trúc phân tán (HTTP, A2A protocol, ReAct sub-agent, nhiều hop).

🎯 Câu hỏi 2 — Giảm latency thế nào?

Phân tích per-node baseline Stage 4 cho thấy chuỗi tuần tự là thủ phạm:

analyze_law 2.65s → check_routing(LLM) 0.93s → [tax‖compliance] 1.93s → aggregate 2.59s = 8.09s

Phương án (đã đo thật):

  • ① Bỏ LLM router → dùng keyword routing (tức thời, 0 lời gọi LLM): cắt thẳng 0.93s khỏi critical path.
  • ② Chạy analyze_law SONG SONG với tax/compliance — vì cả 3 chỉ cần question, không phụ thuộc nhau. Dùng set_conditional_entry_point + Send() để fan-out ngay từ đầu.

Kết quả đo: khối fan-out song song hoàn tất ở 3.24s (so với baseline mất 5.51s mới tới aggregate → nhanh hơn 41% ở pha tiền-tổng-hợp). Cộng aggregate 2.59s ⇒ tổng ≈5.8s, giảm ~28% so với 8.09s.
